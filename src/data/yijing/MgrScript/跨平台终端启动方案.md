## 一、背景与问题

### 现状
- `src/data/yijing/MgrScript/` 下的 Python 脚本（`yijing_manager.py`, `sync_structure.py`, `lock_manager.py` 等）是**独立的数据库管理工具**，和主程序无 import 关系
- macOS 上通过 `.command` 文件双击运行，调用 `python3 xxx.py`
- 这些脚本 import 的都是同目录的兄弟模块（`sync_core`, `sync_structure`, `lock_utils`）+ Python 标准库

### 问题
1. **`.command` 不跨平台**：Windows 不支持 `.command` 文件
2. **依赖系统 Python**：`.command` 里写的是 `python3 xxx.py`，打包给用户后，别人电脑没装 Python 就跑不了
3. **PyInstaller 打包问题**：这些脚本和主程序没有 import 关系 → PyInstaller analysis 不会自动追踪 → 必须手动加入 `datas`（已在 `ZhouyiUnity.spec` 的 `glob("src/data/**")` 中覆盖）

### 核心解决方案
**PyInstaller 打包的 app 自带完整 Python 解释器！**用 `sys.executable` 代替系统 `python3`：
- 开发环境：`sys.executable` = 系统安装的 python3
- 打包后：`sys.executable` = 捆绑在 app 里的 Python 解释器 → 用户无需装 Python

---

## 二、依赖分析：会不会有 import 问题？

### 不会出问题的（当前 MgrScript 就是这种情况）
- **标准库**：`json`, `os`, `sys`, `re`, `shutil`, `zipfile` 等永远在，不依赖 import 检测
- **同目录本地 import**：`from sync_core import ...`, `from lock_utils import ...` 等 — 这些 `.py` 文件通过 `src/data/**` glob 打包到了 app 里，且和脚本在同一个目录，Python 运行脚本时自动把脚本所在目录加入 `sys.path`

### 会出问题的
- **pip 第三方包**：如果数据库脚本用了一个主程序从来没 import 过的 pip 包 → PyInstaller 不会打包它 → 运行时报 `ModuleNotFoundError`
- 举例：假设以后 `yijing_manager.py` 用了 `from rich import print`，而主程序从不 import `rich` → 打包后运行数据库脚本就会报错

### 解决方案（如将来新增第三方依赖）
- 在 `ZhouyiUnity.spec` 的 `hiddenimports` 列表中添加该包名
- 或：在主程序某个不显眼的位置加上 `import rich`（确保 PyInstaller 检测到）
- 最好：数据库脚本保持零第三方依赖，所有功能用标准库实现

### 文件 1：`src/utils/terminal_launcher.py`（新建）

```python
"""
跨平台终端启动器 — 在新终端窗口中用捆绑 Python 运行脚本。

dev 模式用 sys.executable（即系统 python3），
frozen 模式用 PyInstaller 捆绑的 Python 解释器 → 用户无需安装 Python。
"""
import sys
import os
import subprocess


def launch_python_script(work_dir: str, script_name: str, *args: str) -> None:
    """
    在新终端窗口中运行 Python 脚本。

    Args:
        work_dir:    脚本所在目录（绝对路径）
        script_name: 脚本文件名（如 "yijing_manager.py"）
        *args:       传给脚本的额外命令行参数

    用法:
        launch_python_script(
            "/path/to/MgrScript",
            "yijing_manager.py"
        )

    平台行为:
        macOS:   osascript → Terminal.app 新窗口
        Windows: start cmd /k → 新 cmd 窗口
        Linux:   x-terminal-emulator（如可用）
    """
    python = sys.executable
    script_path = os.path.join(work_dir, script_name)
    if not os.path.isfile(script_path):
        print(f"[终端启动] ❌ 脚本不存在: {script_path}")
        return

    extra = " ".join(f'"{a}"' for a in args) if args else ""
    cmd = f'cd "{work_dir}" && "{python}" "{script_path}" {extra}'.strip()

    if sys.platform == "darwin":
        # macOS: osascript 启动 Terminal.app 新窗口
        escaped = cmd.replace('"', '\\"')
        subprocess.run([
            "osascript", "-e",
            f'tell app "Terminal" to do script "{escaped}"'
        ])
        print(f"[终端启动] ✓ macOS Terminal: {script_name}")

    elif sys.platform == "win32":
        # Windows: start 打开新 cmd 窗口
        subprocess.run(
            ["start", '"ZhouyiTools"', "cmd", "/k", cmd],
            shell=True
        )
        print(f"[终端启动] ✓ Windows cmd: {script_name}")

    else:
        # Linux: 尝试常见终端模拟器
        for term in ["gnome-terminal", "x-terminal-emulator", "xterm"]:
            try:
                subprocess.run([term, "--", "bash", "-c", cmd])
                print(f"[终端启动] ✓ Linux {term}: {script_name}")
                return
            except FileNotFoundError:
                continue
        print(f"[终端启动] ❌ 未找到可用的终端模拟器")
```

## 五、实现时注意事项

### 必须做的事
1. **验证 dev 模式**：跑 `python3 -c "from src.utils.terminal_launcher import launch_python_script; launch_python_script('src/data/yijing/MgrScript', 'yijing_manager.py')"` → 弹出 Terminal 窗口，确认正常
2. **验证 build 后**：`bash build/build.sh` → 在打包后的 app 里调用（或手动：`cd dist/ZhouyiUnity && ./ZhouyiUnity` 然后通过某个触发点测试），确认终端窗口弹出且脚本运行
3. **验证 Windows**：在 Windows 上双击 `.bat` → 弹出 cmd 窗口 → 选 1 → 正常运行
4. **检查 import 依赖**：确认 MgrScript 每个 .py 的 import 不超过标准库 + 同目录兄弟模块
5. **调试信息**：所有加载失败处打印 `[终端启动] ❌ 描述 + 路径`，别 silent fail，自动化抓取调试信息自动测试验证。

### 不要做的事
- 不要假设用户装了 Python（打包后用 `sys.executable`）
- 不要假设 Terminal.app 是唯一终端（Windows/Linux 用对应命令）
- 不要只测一个平台就汇报「完成了」
- 不要等用户帮你测试再修问题，确定完整能工作了再告诉用户。
