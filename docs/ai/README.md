## 维护规则

### PITFALLS.md — 踩坑库

**何时加**：任何导致 ≥30 分钟排查时间的 bug，修复后发现是 Qt/PySide6/Python 的通用陷阱。

**格式**：
```markdown
### 标题（现象关键词）
- **现象**：一句话描述
- **根因**：一行说明
- **修复**：具体做法
- **适用范围**：哪些场景会碰到
```

**归类**：归入已有 7 大类之一（布局引擎 / Widget尺寸 / PySide6 API / 信号事件 / CSS样式 / 构建打包 / 通用逻辑），没有匹配的类就新建。

### modules/*.md — 模块架构

**何时更新**：
- 新增/删除文件 → 更新文件分层树
- 新增组件/公开API → 更新 API 表格
- 新增设计模式 → 更新设计模式章节
- 参数变更 → 更新 CONST_DEFINE_UI 表格

**不需要更新**：内部实现细节变化、小 bug 修复、样式微调。

### CONVENTIONS.md — 编码规范

**何时更新**：新增了全局强制约定（不是某个模块特有的）。

判断标准：换一个 Tab/模块开发，这个规则是否也必须遵守？是 → CONVENTIONS.md，否 → 模块 md。

### CHANGELOG.md — 变更历史

**何时更新**：完成一个相对独立的功能模块或重要 bug 修复后，加一行摘要。

日常 commit 级别的细碎变更不需要。

## 代码完成后的维护 Checklist

```
□ 有没有发现新踩坑？                     → PITFALLS.md
□ 有没有新增/修改组件 API？              → modules/<模块>.md
□ 有没有新增/修改设计模式？              → modules/<模块>.md
□ 有没有新增全局编码规范？               → CONVENTIONS.md
□ 这个功能值得记录在变更历史吗？          → CHANGELOG.md
```

不是每个改完都要全打勾。大多数小改动 5 项全跳过。关键是自己判断：**未来的 AI 遇到同样场景需要知道吗？**
