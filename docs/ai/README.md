## 维护规则

### PITFALLS.md — 踩坑库

**何时加**：任何导致 ≥30 分钟排查时间的 bug，修复后发现是 Qt/PySide6/Python 的通用陷阱。

**格式**：
```markdown
### 标题（现象关键词）
- **现象**：一句话描述
- **根因**：一行说明
- **修复**：具体做法
- **来源**：文件 + 场景
- **适用范围**：哪些场景会碰到
```

**归类**：归入已有 7 大类之一（布局引擎 / Widget尺寸 / PySide6 API / 信号事件 / CSS样式 / 构建打包 / 通用逻辑），没有匹配的类就新建。

**⚠️ 同步索引**：新增/修改/删除踩坑条目后，**必须**同步更新文件顶部的「症状速查索引」表。索引每行 ≤1 行，仅症状关键词 + 根因一句话 + 章节号。索引是 AI 的第一层扫描，过时会导致读错章节浪费 token。

### modules/*.md — 模块架构

**何时更新**：
- 新增/删除文件 → 更新文件分层树
- 新增组件/公开API → 更新 API 表格
- 新增设计模式 → 更新设计模式章节
- 参数变更 → 更新 CONST_DEFINE_UI 表格

**不需要更新**：内部实现细节变化、小 bug 修复、样式微调。

### CONVENTIONS.md — 编码规范

**何时更新**：新增了全局强制约定（不是某个模块特有的）。

判断标准：换一个 Tab/模块开发，这个规则是否也必须遵守？是 → CONVENTIONS.md，否 → 模块 md。

### CHANGELOG.md — 变更历史

**何时更新**：完成一个相对独立的功能模块或重要 bug 修复后，加一行摘要。

日常 commit 级别的细碎变更不需要。

## 路径同步机制

**问题**：PITFALLS.md 的「来源」字段和模块 md 里引用的文件路径，在代码重构/重命名后会变成死链接。

**规则**：任何涉及文件移动/重命名/拆分/合并的操作：

1. **操作前** — `grep -r "旧路径" docs/ai/` 找出所有引用
2. **操作后** — 逐条更新为新路径
3. **验证** — `grep -r "旧路径" docs/ai/` 应无结果

示例：
```bash
# 把 divination_panel.py 拆成多个文件前
grep -r "divination_panel.py" docs/ai/
# 拆分后更新所有引用为新路径，再次 grep 确认无残留
```

路径格式统一为**仓库相对路径**（如 `yijingTab/qigua/divination_panel.py`），不含 `src/` 前缀（因为 src 层不太可能改名）。

## 代码完成后的维护 Checklist

```
□ 有没有发现新踩坑？                     → PITFALLS.md（含顶部索引同步）
□ 有没有文件移动/重命名？                → grep docs/ai/ 同步路径
□ 有没有新增/修改组件 API？              → modules/<模块>.md
□ 有没有新增/修改设计模式？              → modules/<模块>.md
□ 有没有新增全局编码规范？               → CONVENTIONS.md
□ 这个功能值得记录在变更历史吗？          → CHANGELOG.md
```

不是每个改完都要全打勾。大多数小改动 5 项全跳过。关键是自己判断：**未来的 AI 遇到同样场景需要知道吗？**

## AI 行为规则（换机器不丢失）

> **本文件是 AI 行为规则的唯一权威来源**。
> - 所有编码/测试/维护规则**只记录在本目录**，禁止在 `~/.claude/` 创建新的行为规则记忆文件
> - 现有 `~/.claude/` 记忆文件仅做加速缓存，与本文件冲突时以本文件为准
> - 规则变更只需更新本文件 + 对应的 docs/ai/ 子文件
> - 换电脑/更换项目路径后，clone 仓库即自带全部规则，无需额外配置。CLAUDE.md 自动加载 → 导航表指向本文件 → 全部规则生效
> - `~/.claude/` 记忆文件绑定了项目路径，更换路径后旧记忆自动失效（但无关紧要，因本文件是权威来源）

### 编码前
1. **必读 CLAUDE.md 导航表** — 按场景确定需要读哪些 docs/ai/ 文件
2. **遇到 UI bug → 先读 PITFALLS.md 顶部索引**（~30行），匹配症状才跳章节，不加载全文件
3. **PySide6 API 不确定 → PITFALLS §3**
4. **修改模块代码 → 先读 modules/<模块>.md**

### 编码中
5. **所有代码变更必须在 _debug/ 生成测试脚本**，通过后才算完成
6. **测试用双通道日志**：正确输出 ✅ 给用户看，错误输出写入 `.err.log` 给 AI 修复，节省 token
7. **发现耗时 > 30 分钟的坑 → PITFALLS.md 完整记录**：失败尝试列表 + 为什么测试没发现 + 代码对比 + 检测方法

### 编码后
8. **按维护 Checklist 逐项判断**，同步更新相关 doc
9. **新增踩坑** → PITFALLS.md（含来源字段 + 索引同步）
10. **文件移动/重命名** → `grep -r "旧路径" docs/ai/` 同步所有引用
11. **新增 _debug 测试脚本** → 同步更新 `_debug/README.md` 表格

### 禁止
- 凭记忆写代码（必须先读 docs/ai/）
- `Read PITFALLS.md` 无参数加载全文件（先读索引）
- 改了代码不跑测试就汇报完成
- 发现踩坑只记一句话（耗时长的必须展开）
- 重构文件后不更新 docs/ai/ 路径引用
